What this demo does not do yet

  • Devanagari only: Tamil planned for v0.2 (a design note exists; nothing is implemented), Bengali later. Text in any other script is treated as plain text, so a Latin line scores clean.
  • Structural checks only: it cannot see visually plausible OCR confusions (ब for व), a well-formed but wrong word, or legacy-font text that was read back as Latin letters.
  • The rule weights are not calibrated on real documents: they come from how badly each defect breaks rendering or reading, and the benchmark behind them uses synthetic text only.
  • UTF-8 text only, at most 1 MiB: no PDF, no OCR, no other encodings.
  • No service worker: offline after the first load is best effort (Chrome's HTTP cache), not guaranteed.
  • Nothing is published yet: the Python wheel and the npm package were built and installed locally on macOS arm64 only, and are on no registry. Linux and Windows wheels are built only by CI after the owner's push.

Document score

—

Each flagged cluster costs the largest weight among its issues; the score is 1 − penalty × 1000 ÷ clusters, in parts per million, shown with four decimals (truncated, never rounded) by integer arithmetic. 1.0000 is clean; empty text scores 1.0000.

Heatmap

One row per line: a strip for the line, then every grapheme cluster of the line. A cluster is shaded by the sum of the weights of the rules that fired on it; the strip uses the same sum over the whole line. Hover a shaded cluster to see the rules. Invisible, control and private-use code points are shown as ⟨U+XXXX⟩.

  • clean: no rule fired
  • low: weight sum 1 to 399
  • mid: 400 to 799
  • high: 800 and above
